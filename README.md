# Salyq AI

ИИ-бухгалтер для ИП на упрощённом режиме (форма 910.00) в Казахстане. Техническое
задание — [`docs/spec.md`](docs/spec.md).

- **Бэкенд:** Python 3.12, FastAPI, SQLAlchemy 2, PostgreSQL 16, Celery + Redis.
- **Веб-клиент:** Next.js 15 (статическая сборка + nginx).

## Что готово

| Раздел ТЗ | Что работает | Код |
|---|---|---|
| 4.1 Онбординг | Вход по ЭЦП (NCALayer → NCANode), согласия с версиями, профиль ИП | `salyq/auth`, `web/app/login`, `web/app/consents` |
| 4.2 Импорт | Выписка Kaspi Business (PDF, XLSX, CSV), дедупликация по банку, дате, сумме и референсу | `salyq/statements` |
| 4.3 Разметка | Правила + локальная LLM, уверенность, очередь «Проверить», персональные правила, курс НБ РК | `salyq/categorize`, `salyq/fx.py` |
| 4.4 Налог | Налог по ставке региона, раздельный учёт регионов, соцплатежи, лимит 50/80/95%, «Как посчитано» | `salyq/tax` |
| 4.5 Форма 910.00 | Черновик, проверки, проверка экспертом, подпись ЭЦП, выгрузка XML | `salyq/declarations` |
| 4.6 Копилка и напоминания | «Отложить N ₸», напоминания e-mail и Telegram по срокам года | `salyq/tax/summary.py`, `salyq/reminders` |
| 4.7 AI-чат | RAG по базе знаний, инструменты движка, локальная или внешняя модель, «Передать эксперту» | `salyq/chat` |
| 4.8 Админ-панель | Очередь возражений (3 рабочих дня), вопросов и деклараций; доступ к данным по обращению; версии ставок | `salyq/api/admin.py`, `web/app/admin` |
| 2, 6 Право и безопасность | Шлюз обезличивания, шифрование ПДн, журнал действий только на добавление, возражения по ст. 19-1 | `salyq/privacy`, `salyq/crypto.py` |

Проверено: 352 теста на SQLite и PostgreSQL (схема строится из миграций). Весь путь ИП
(вход → согласия → выписка → разметка → налог → возражение → 910.00 → чат) и путь эксперта
пройдены в Chromium через Playwright.

## Запуск

```bash
docker compose up --build          # БД, миграции, API :8000 (/docs), веб :3000, фоновые задачи
docker compose run --rm tests      # тесты бэкенда, включая PostgreSQL
```

Откройте http://localhost:3000. В режиме разработки есть вход без ЭЦП: введите любой
корректный ИИН и ФИО. Назначить пользователя экспертом:

```bash
docker compose exec api python -m salyq.cli make-expert --iin <ИИН>
```

Локально без Docker:

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env               # заполнить ключи шифрования
alembic upgrade head
uvicorn salyq.main:app --reload
pytest                             # тесты на PostgreSQL — с TEST_DATABASE_URL

cd web && cp .env.example .env.local && npm install && npm run dev
```

## Настройки (переменные `SALYQ_*`)

| Переменная | Назначение |
|---|---|
| `DATABASE_URL`, `REDIS_URL` | PostgreSQL, Redis для фоновых задач |
| `FIELD_KEY`, `HMAC_KEY` | ключи шифрования полей и слепых индексов (base64, 32 байта; в проде — из KMS/Vault в РК) |
| `ENVIRONMENT` | `dev` / `test` / `prod`; в `prod` вход без ЭЦП запрещён |
| `ECP_VERIFIER`, `NCANODE_URL` | `dev` (заглушка) или `ncanode` + адрес NCANode |
| `LLM_BASE_URL`, `LLM_MODEL` | локальная модель (vLLM, OpenAI-совместимый API) для разметки и чата |
| `EXTERNAL_LLM_BASE_URL`, `EXTERNAL_LLM_MODEL`, `EXTERNAL_LLM_API_KEY` | внешняя модель для чата (только с согласием, через шлюз, только zero data retention) |
| `SMTP_*`, `TELEGRAM_BOT_TOKEN` | каналы напоминаний |
| `DECLARATION_EXPERT_REVIEW` | пилот: подпись 910.00 только после проверки экспертом (по умолчанию да) |
| `SENTRY_DSN`, `CORS_ORIGINS` | Sentry (self-hosted в РК), адрес веб-клиента |

Без `LLM_BASE_URL` всё работает: разметка — правилами, чат — по базе знаний и инструментам.

## API (v1)

Полная схема — `/docs`. 🔒 — нужны вход и согласие на обработку ПДн; 👤 — только эксперт.

| Путь | Назначение |
|---|---|
| `POST /auth/ecp/challenge`, `POST /auth/ecp`, `DELETE /auth/session` | вход по ЭЦП и выход |
| `GET/PATCH /me`, `PATCH /me/notifications` | профиль, каналы напоминаний |
| `GET/POST /consents`, `DELETE /consents/{type}` | согласия |
| 🔒 `POST /statements` | загрузка выписки (`file`, `bank`) |
| 🔒 `GET /transactions?status=review`, `PATCH /transactions/{id}`, `POST /transactions/confirm-suggested` | очередь «Проверить», подтверждение |
| 🔒 `GET /tax/summary?period=2026H2`, `GET /tax/calculations/{id}/explain` | налог, соцплатежи, лимит, копилка; «Как посчитано» |
| `POST /tax/simplified`, `POST /tax/self-social` | калькуляторы без ПДн |
| 🔒 `POST /declarations/910`, `GET /declarations/910/{id}`, `POST …/sign`, `GET …/export` | форма 910.00 |
| 🔒 `POST/GET /objections` | возражения по ст. 19-1 |
| 🔒 `POST/GET /chat/messages`, `POST /chat/escalate`, `GET /chat/questions` | AI-чат |
| 👤 `/admin/queue`, `/admin/access`, `/admin/objections/…`, `/admin/questions/…`, `/admin/declarations/…`, `/admin/tax-config…`, `/admin/region-rates` | кабинет эксперта |
| `GET /metrics` | Prometheus (закрыть от внешнего мира на ingress) |

## Как устроено

**Деньги и налог.** Все суммы — в тиынах (`int`), `float` запрещён. Параметры года
(МРП, МЗП, ставки, лимиты, сроки) — в YAML, проверяются схемой. Действует последняя
версия, **утверждённая экспертом** в БД; файл из репозитория считается черновиком, и
расчёты по нему помечаются `CONFIG_NOT_APPROVED`. Налог считается только с
**подтверждённых пользователем** поступлений категории «доход от реализации», в тенге по
курсу НБ РК. Каждый расчёт сохраняется со «следом»: версия и sha256 параметров, операции,
формулы и шаги. По следу строится экран «Как посчитано».

**Разметка.** Сначала персональные правила пользователя, затем переводы между своими
счетами (по ИИН и IBAN), затем правила из `rules.yaml`. Если уверенность ниже 0,85, при
наличии локальной модели вызывается LLM. Неизвестное поступление всегда попадает на
проверку. Подтверждение пользователя пишется в журнал и становится правилом для
контрагента. Без согласия по ст. 19-1 категории не предлагаются.

**Форма 910.00.** Черновик → проверки → проверка экспертом (пилот) → подпись ЭЦП → выгрузка.
Проверки:

- полугодие закончилось;
- все операции подтверждены;
- выписки покрывают период по каждому счёту;
- лимит режима не превышен;
- регион указан в профиле;
- ставки утверждены экспертом.

Подписывается sha256 документа. При подписи сервер сверяет, что подписал сам ИП и что
данные не изменились после проверки.

**Персональные данные.**

- ПДн шифруются на уровне полей (AES-256-GCM): ИИН, ФИО, IBAN, контрагенты, назначения,
  сообщения чата, тексты обращений, подписи.
- Поиск идёт по HMAC-индексам.
- Журнал действий — только добавление (триггер в PostgreSQL), без ПДн.
- Эксперт видит данные клиента только по открытому обращению, на 2 часа, и каждый
  просмотр попадает в журнал.

**Внешняя LLM.** Только с согласием на трансграничную передачу и только через
`prepare_external`:

- ИИН, БИН, IBAN, карты, телефоны, e-mail, ФИО и адреса заменяются токенами;
- суммы заменяются диапазонами;
- при остаточных ПДн запрос блокируется.

Точные цифры пользователь видит в карточках от движка, модель их не пересказывает.

**Выписки.** Колонки определяются по синонимам, PDF разбирается через pdfplumber.
Дедупликация:

- с референсом — по банку, счёту, дате, сумме и референсу, поэтому PDF и XLSX за один
  период не дают дублей;
- без референса — по содержимому строки и порядковому номеру среди одинаковых строк.

## Разработка

```bash
alembic revision --autogenerate -m "..."   # после правки salyq/models.py; alembic check — сверка
ruff check salyq tests migrations/env.py
cd web && npm run typecheck && npm test && npm run build
```

CI (GitHub Actions) прогоняет линтер, тесты на PostgreSQL, `alembic check` и сборку
веб-клиента. Тестовые выписки в `tests/fixtures` синтетические;
`make_kaspi_pdf.py` пересоздаёт PDF.

```
salyq/
  auth/          вход по ЭЦП (ecp.py: dev, NCANode), сессии, согласия, журнал
  statements/    парсер Kaspi, сохранение с дедупликацией
  categorize/    категории, rules.yaml, LLM-классификатор, очередь и подтверждения
  tax/           движок, параметры по годам, версии в БД, ставки регионов, сводка
  declarations/  форма 910.00
  chat/          база знаний (kb/*.md), инструменты, провайдеры LLM
  privacy/       шлюз обезличивания
  reminders/     напоминания и каналы
  objections.py, expert_access.py, workdays.py, fx.py, crypto.py, http.py, observability.py
  api/           роутеры FastAPI
  worker.py, cli.py
migrations/      Alembic
web/             Next.js-клиент
```
