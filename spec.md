# Salyq AI — техническое задание

Версия от 06.10.2026

## 1. Цель и границы MVP

**Видение продукта:** ИИ-бухгалтер, который полностью закрывает налоговые обязательства ИП — от выписки до сданной декларации и оплаченного налога — за подписку дешевле бухгалтера на аутсорсе. От клиента требуется только одно касание: подтвердить и подписать ЭЦП. MVP — первый шаг к этому; полная автоматизация наступает поэтапно (раздел 7).

Salyq AI — мобильное и веб-приложение, которое ведёт налоговый учёт ИП на упрощённой декларации в Казахстане: собирает поступления из банков, считает налог и соцплатежи, готовит форму 910.00 и отвечает на вопросы в чате. Цель MVP — за 4–6 месяцев проверить, что 30–50 пилотных ИП пользуются продуктом каждый месяц и готовы платить подписку.

**Целевая аудитория MVP:** ИП на СНР на основе упрощённой декларации, без работников или с 1–3 работниками; фрилансеры с доходом от казахстанских и иностранных заказчиков.

**Входит в MVP:**

- Регистрация и вход через ЭЦП или eGov Mobile, согласия на обработку данных.
- Загрузка банковских выписок (Kaspi, Halyk, Freedom) файлом; API-интеграции — второй этап.
- Автоматическая разметка операций локальной моделью с подтверждением пользователем.
- Налоговый движок: налог по ставке региона, соцплатежи за себя, учёт лимита режима, пересчёт валюты по курсу Нацбанка.
- Копилка и напоминания о сроках.
- Черновик формы 910.00 для проверки и подписи пользователем.
- AI-чат по общим налоговым вопросам.
- Админ-панель для бухгалтера-эксперта.

**Не входит в MVP:** ИП на общеустановленном режиме и плательщики НДС, ТОО, расчёт зарплаты работников, автоматическая отправка 910.00 без подписи пользователя, приём платежей за налоги внутри приложения.

## 2. Правовые требования

Все персональные данные клиентов хранятся и обрабатываются в Казахстане; за рубеж уходят только обезличенные запросы и только с отдельного согласия. Требования ниже — по редакции Закона № 94-V на 25.08.2026; подтвердить у юриста до начала разработки.

| Требование | Норма | Как реализуем |
| --- | --- | --- |
| Хранение данных в Казахстане | п. 2 ст. 12 Закона № 94-V | Все БД, файлы выписок, бэкапы и логи — в ЦОДе на территории РК |
| Обработка данных ограниченного доступа в РК | п. 13 Правил (приказ № 179/НҚ) | Разметка операций и расчёты — только на серверах в РК, локальная LLM |
| Согласие на сбор и обработку | ст. 8 Закона № 94-V | Экран согласий при регистрации, версия и дата согласия в БД, отзыв в настройках |
| Трансграничная передача | ст. 16 Закона № 94-V | Отдельное необязательное согласие; до отправки — обезличивание; без согласия чат работает на локальной модели |
| Автоматизированная обработка с правовыми последствиями | ст. 19-1 Закона № 94-V | Согласие; объяснение логики; кнопка «Возразить»; рассмотрение возражения за 3 рабочих дня; 910.00 подписывает человек |
| Права при алгоритмических решениях | ст. 43 Цифрового кодекса | Экран «Как посчитано» с ключевыми факторами; пересмотр экспертом по запросу |
| Ответственное лицо, инвентаризация процессов, внутренний контроль | Правила (приказ № 179/НҚ в ред. № 338/НҚ) | Приказ о назначении; реестр процессов обработки; журнал действий |
| Уведомление об утечке | Правила (приказ № 481/НҚ) | Уведомление регулятора в течение 1 рабочего дня |

На старте сервис попадёт в малую категорию по ст. 25-1 (до 10 000 уникальных субъектов), но банковские данные могут быть отнесены к данным ограниченного доступа, что повышает категорию на уровень.

Отдельно проверить: требования Закона «Об искусственном интеллекте» № 230-VIII и есть ли ограничения на ведение налогового учёта третьими лицами.

## 3. Архитектура

Все компоненты, которые видят персональные данные, работают в одном ЦОДе в Казахстане; наружу ведут только два канала — eGov для ЭЦП и внешняя LLM через шлюз обезличивания.

```
Приложение (iOS, Android, веб)
        │
        ▼
┌──────────── Казахстан · ЦОД ────────────┐
│ API-бэкенд (авторизация, согласия, audit)│──► eGov / NCALayer (вход, подпись 910.00)
│   ├─► Налоговый движок (код, не LLM) ──► PostgreSQL (шифрование полей)
│   ├─► Разметка операций (правила + LLM) ─► Локальная LLM (vLLM, GPU в РК)
│   └─► AI-чат (RAG + инструменты) ──► Локальная LLM
│                                  └──► Шлюз обезличивания ──► Внешняя LLM
└──────────────────────────────────────────┘           (только с согласием)
```

| Слой | Технология |
| --- | --- |
| Мобильное приложение и веб | React Native (Expo) + Next.js |
| Бэкенд | Python 3.12, FastAPI, SQLAlchemy, Celery |
| Данные | PostgreSQL 16, Redis, S3-совместимое хранилище в РК |
| Локальная LLM | открытая модель 7–32B, vLLM, OpenAI-совместимый API; KazLLM / AlemLLM — кандидаты для казахского языка |
| Инфраструктура | Docker, docker compose на старте, Kubernetes позже; облако с GPU в РК |
| Наблюдаемость | Prometheus, Grafana, Sentry (self-hosted в РК) |

## 4. Функциональные требования

Налог и сроки считает детерминированный код; LLM только размечает операции и объясняет.

**4.1 Онбординг и профиль**
- Вход через ЭЦП (NCALayer / eGov Mobile, QR); ИИН из сертификата.
- Согласия: обработка ПДн (обязательно), автоматизированная обработка по ст. 19-1 (обязательно для авторазметки), трансграничная передача (необязательно).
- Профиль ИП: регион, дата регистрации, работники. Ставка — из справочника ставок маслихатов.

**4.2 Банки и импорт**
- Загрузка выписок PDF / XLSX из Kaspi Business, Halyk, Freedom; парсер под каждый банк.
- Дедупликация по банку, дате, сумме и референсу.
- Этап 2: API-интеграции с банками.

**4.3 Операции и разметка**
- Категории: доход от реализации, личный перевод, возврат, перевод между своими счетами, соцплатежи, налоги, прочий расход.
- LLM + правила дают категорию и уверенность 0–1; ниже порога (0,85) — очередь «Проверить».
- Подтверждения пользователя пишутся в журнал и создают персональные правила.
- Валюта пересчитывается по курсу Нацбанка на дату поступления; курс хранится с операцией.

**4.4 Налоговый движок**
- Налог за полугодие = облагаемый доход × ставка региона; раздельный учёт при нескольких регионах.
- Соцплатежи за себя (ОПВ, ОПВР, СО, ВОСМС) по ставкам из конфигурации года.
- Контроль лимита режима (2026: 2 595 000 000 тенге за полугодие), предупреждения на 50/80/95%.
- Ставки, МРП, МЗП, лимиты, сроки — в версионируемой конфигурации по годам; изменения утверждает эксперт.
- Каждый расчёт хранит «след» (операции, ставки, версия конфигурации) для экрана «Как посчитано».

**4.5 Форма 910.00**
- Автосборка черновика из подтверждённых операций.
- Проверки: нет неподтверждённых операций, совпадение с выписками, лимит не превышен.
- Экспорт для Кабинета налогоплательщика; подпись ЭЦП пользователем. Прямая отправка — этап 2.

**4.6 Копилка и напоминания**
- Рекомендация «отложить N тенге» с каждого дохода.
- Push, e-mail, Telegram: сроки 910.00, налога, соцплатежей (из конфигурации).

**4.7 AI-чат**
- RAG по проверенной базе знаний и НПА.
- Без согласия на трансграничную передачу — только локальная модель.
- Инструменты: «посчитать налог», «показать операции», «сравнить ставки»; цифры — из движка.
- «Передать эксперту».

**4.8 Админ-панель**
- Очередь вопросов и возражений по ст. 19-1 с таймером 3 рабочих дня.
- Управление конфигурацией ставок и сроков.
- Доступ к данным клиента только по обращению, с записью в журнал.

## 6. Безопасность и нефункциональные требования

- Шифрование: TLS 1.2+, шифрование дисков и бэкапов, шифрование полей (ИИН, ФИО, IBAN, контрагенты) ключами из KMS / Vault в РК. Криптография по СТ РК 1073-2007 — уточнить у юриста.
- Доступ сотрудников: роли, VPN, 2FA; доступ к данным клиента по обращению, с записью в audit_log.
- Обезличивание перед внешней LLM: удалить ИИН, БИН, IBAN, телефоны, ФИО, адреса; суммы — диапазонами; блокировать запрос при остаточных ПДн.
- Внешние LLM: только zero data retention, договор с провайдером.
- SAST/DAST в CI, внешний пентест до пилота.
- План реагирования: уведомление регулятора в течение 1 рабочего дня.

## 7. План работ до полного ИИ-бухгалтера

| Этап | Сроки | Содержание | Контрольная точка |
| --- | --- | --- | --- |
| Подготовка | месяц 1 | заключение юриста, выбор ЦОДа и модели, тест разметки | юрист одобрил |
| MVP | месяцы 2–4 | импорт выписок, налоговый движок, 910.00 на подпись | пентест пройден |
| Пилот | месяцы 5–6 | 30–50 ИП, эксперт проверяет каждую 910.00 | пилот без ошибок в 910.00 |
| ИИ-бухгалтер | месяц 7+ | API банков, автосдача и оплата, работники и ОУР | — |

**Почему дешевле бухгалтера:** ИИ и код делают рутину, один эксперт разбирает только спорные случаи сотен клиентов.

**Команда до пилота:** backend-разработчик (Python), mobile/web-разработчик, ML/DevOps-инженер (частично), бухгалтер-эксперт по упрощёнке РК (частично), юрист по персональным данным (разово).

**Открытые вопросы:**
- [ ] Юрист: может ли сервис сдавать 910.00 и платить налоги от имени ИП?
- [ ] Юрист: банковские выписки — данные ограниченного доступа? Категория по ст. 25-1?
- [ ] Юрист: ответственность за ошибку в декларации, нужно ли страхование?
- [ ] Бухгалтер: ставки и базы соцплатежей 2026, сроки сдачи 910.00 и уплаты по новому НК.
- [ ] Бухгалтер: какие поступления не являются доходом — правила для движка.
- [ ] Продукт: цены бухгалтеров на аутсорсе и цена подписки.
